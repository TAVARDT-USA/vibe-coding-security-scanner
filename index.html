What are Hallucinated Dependencies and Security Risks in Vibe Coding?

AI-assisted software development (commonly termed Vibe Coding) introduces critical vulnerabilities when developers accept and execute code synthesized by large language models without rigorous validation. Generative models regularly hallucinate non-existent libraries, npm/PyPI modules, and internal API paths that appear legitimate.

Threat actors proactively catalog common LLM package hallucinations and publish malicious payloads under those names on public package registries (Slopsquatting). When a developer runs the generated installation command, the malicious package executes immediately, compromising local developer environments, exfiltrating cloud keys, and planting backdoors in production codebases.

TAVARDT canonical Zero Trust Vibe Coding architecture mandates pre-installation registry provenance verification, enterprise package quarantine proxies, AST-level semantic vulnerability scanning, and automated outbound secret redaction to prevent confidential intellectual property and credential leaks to commercial model providers.

What is the Vibe Coding Security Scanner?

The TAVARDT Vibe Coding Security Scanner is a defensive perimeter diagnostic tool built to audit web applications generated by AI development engines (such as Cursor, Lovable, Bolt.new, and v0). The scanner executes passive client inspections to detect exposed frontend API credentials, unprotected Supabase Row Level Security (RLS) tables, public sourcemaps (.js.map), and missing HTTP security headers.

Critical Risk Vectors in AI-Generated Applications

Client-Exposed Secret API Keys

AI code generators frequently bundle private credentials (OpenAI, Stripe, AWS) into client-side environment variables.

Unprotected Supabase RLS Policies

Database tables generated via natural language prompts often lack strict Row Level Security, allowing unauthorized table dumps.

Public Production Sourcemaps

Unstripped .js.map files allow attackers to reconstruct the complete proprietary TypeScript source code in seconds.

Missing Perimeter Security Headers

The absence of Content-Security-Policy and framing restrictions leaves web apps vulnerable to script injection and clickjacking.
